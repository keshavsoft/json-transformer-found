Why does the result have one receipt?

The answer is in the two JSON files. The source contains two root collections, but the recipe names only one. Then the nested rules unwrap a handful of fields from that one selected record.

2root collections in source
1root key selected by recipe
1record in selected collection

1. Read the source

samples/new/receipts/structure.json is passed as the first argument. Its root has a one-record Receipts array and a separate Receipts1 array with 916 records.

2. Read the recipe

samples/new/receipts/data.json is passed as the second argument. At the root, its transform map has only the key Receipts. The nested Receipts recipe then selects five fields from each item.

Full recipeinstruction JSON
{
  "transform": {
    "Receipts": {
      "alterKey": "Receipts",
      "valueType": "array"
    }
  },
  "Receipts": {
    "transform": {
      "date": { "valueKey": "value" },
      "ledgername": { "valueKey": "value" },
      "vouchernumber": { "valueKey": "value" },
      "isdeemedpositive": { "valueKey": "value" },
      "amount": { "valueKey": "value" }
    }
  }
}

3. Trace the transformation

01

Select the root key. The executor walks the source root. Receipts matches the transform map; Receipts1 does not, so its 916 records never enter the result.

02

Keep the collection as an array. alterKey keeps the name Receipts. The source is already an array, so valueType: "array" leaves it as-is.

03

Visit the one item. Array traversal passes the nested receipt recipe to the item object.

04

Unwrap selected values. Each selected child object is reduced to its value property. The other source fields are omitted.

Receipts→ selectarray of 1→ map item5 fields→ unwrapresult

4. See the result

Output from the selected source recordresult JSON
{
  "Receipts": [
    {
      "date": "20260401",
      "ledgername": "Phonepe Business (Axis)",
      "vouchernumber": "1",
      "isdeemedpositive": false,
      "amount": "1020.00"
    }
  ]
}

The amount remains a string because V3 extracts values without converting them. The boolean remains a boolean. Fields such as metadata and the parent voucher details are absent because the nested transform map does not name them.

A second sample: StockItems

The samples/new/batches recipe selects STOCKITEM, renames it to StockItems, and maps three fields per row. It changes @_NAME to Name, @_RESERVEDNAME to ReserveName, and extracts #text from BASEUNITS as Units.

Representative first rowresult JSON
{
  "Name": "0.09/30mm",
  "ReserveName": "",
  "Units": "kgs"
}

The source has 1,529 stock items. Fields such as HASMFGDATE and BATCHALLOCATIONS.LIST are not in this recipe, so they are omitted.
