Inside V3: traversal first, rules second.

V3 is the implementation reached through the package’s public entry point. The engine has two main jobs: decide how to walk a value, then apply the recipe where a transform map appears.

src/index.js→src/v3/index.js→traversal→execution

Public contract

src/v3/index.jsdefault + named exports
transform(source, recipe)

// Public entry passes both inputs to traversal:
traverse({
  inSource: source,
  inRecipe: recipe,
  inExecute: execute
})

src/index.js re-exports the default and named exports from src/v3/index.js. V3 exports transform, traverse, and execute. The current npm package version is 1.3.1; that semver label is separate from the source folder name.

Follow one value through the engine

01

Dispatch by source shape. traversal/index.js sends arrays to traverseArray, non-null objects to traverseObject, and returns strings, numbers, booleans, and null unchanged.

02

Check the recipe at an object. execution/index.js runs a transform only when the recipe is an object with a transform property. Otherwise it returns the source value unchanged.

03

Walk source entries. ifTransformFound iterates Object.entries(source). It skips a source key unless that key exists in the transform map.

04

Apply the rule in order. V3 resolves the output key, applies a nested transform, normalizes the value type, extracts a value key, then assigns the result to the output object.

Per-key directive pipelineifTransformFound
resolveKey→applyTransform→normalizeValueType→extractValueKey→assign output

This order matters: nested traversal happens before array wrapping, and value extraction happens last.

Traversal behavior

Source valueV3 routeEffect
ArraytraverseArrayMap each item through traversal using the same recipe; flatten nested arrays; remove falsey results.
ObjecttraverseObjectRun the executor, then visit array-valued properties whose keys exist in the current recipe.
Primitive or nullReturn as-isNo further traversal or type conversion.

traverseObject begins with the source object as its working value. If execution returns a transformed object, it uses that object; afterward, matching array children are replaced with traversed arrays.

What each directive does

DirectiveImplementation behaviorExample
transformMarks an object recipe for execution and maps source keys to directives.{ "transform": { "date": {} } }
alterKeyUses the supplied output key; otherwise the input key is kept.{ "alterKey": "Date" }
valueType: "array"Leaves an array unchanged; wraps any non-array value in a one-item array.{ "valueType": "array" }
valueKeyFor a truthy object value, returns its named property directly.{ "valueKey": "#text" }

At a transformed level, the source drives output construction. Recipe entries without matching source keys do not create output fields, and source fields without matching recipe entries are skipped.

Important edge behavior

!

Array filtering can remove data. The array traversal ends with .filter(Boolean). Values such as false, 0, "", null, and undefined are removed from arrays. The receipt’s false survives because it is a field inside an object, not an array item.

i

Source immutability is not guaranteed. When an object has no transform at its own level, traverseObject may replace a matching array property on that same source object with the traversed array.

Other limits visible in V3

  • valueKey is direct lookup; a missing child produces undefined.
  • V3 does not cast strings to numbers or parse dates. Unwrapped values keep the source value’s type.
  • The current directives do not provide computed fields, conditional rules, or defaults.
  • src/v3/execution/objectToArray exists in the tree, but the current V3 execution entry does not import or call it.
